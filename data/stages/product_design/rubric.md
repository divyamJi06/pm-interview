## Intent

Assess ability to approach open-ended product problems like a PM: start
with the user, structure the problem, identify use cases and weak spots,
and design around user needs rather than personal preference.

## Ideal structure

1. Understand the problem
2. Provide a structure
3. Identify users/customers
4. Identify use cases and goals
5. Assess how current solutions serve those use cases
6. Identify features that address weak spots
7. Wrap up the solution

## Scoring dimensions

- User focus — identifies relevant users, designs around their needs rather than personal preference
- Goal & use-case understanding — identifies why users use the product, their tasks and motivations
- Structured thinking — moves through the problem in a clear, organized way
- Problem-to-solution connection — proposed features directly address identified weak spots or use cases
- Solution judgment & simplicity — chooses/refines ideas appropriately; recognizes when simpler is better

## Green flags

- starts by understanding the question, not features
- lays out an explicit structure
- identifies multiple users/customers
- digs into user characteristics beyond a broad label
- considers secondary or indirect users
- identifies concrete use cases, prioritizes among them
- identifies underlying motivation, not just the action
- examines existing solutions' weak spots
- features explicitly tied to use cases or goals
- generates multiple ideas before choosing one
- notes different users may need different things
- weighs tradeoffs between design alternatives
- keeps the design appropriately simple
- clearly summarizes the final recommendation

## Red flags

- jumps to features without understanding the problem
- designs for what the candidate personally wants
- treats users as one homogeneous group
- ignores secondary users
- lists features with no use case/goal tie-in
- skips assessing existing solutions
- features not connected to any goal
- long, unprioritized idea list
- unnecessarily complex design
- no clear final proposal
